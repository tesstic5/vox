Voxera

What Voxera can — and cannot — do

An honest feature list. Everything under “can do” is a working page, route, or tool in the product, verified by an automated test suite (37 test gates, 1,464 checks, all passing). Everything under “cannot do” is stated plainly, with what exists instead.

✅ What it can do

📞 Phone & AI assistants

  • Answer inbound calls and run appointments end-to-end: check availability, book, reschedule, cancel, send confirmations, create payment links, transfer, draft notes
  • Outbound dialling with attempt budgets, quiet hours, and do-not-call enforcement
  • Assistants with versioned configuration (model, voice, prompt, tools), publish and rollback
  • Squads — assistants handing off mid-call with a written brief; Workflows for steps that must not be improvised; Tools & MCP servers allowlisted per assistant and enforced at runtime
  • Knowledge base the assistant answers from, traced back to its source
  • Evals, simulations with synthetic callers, a live API playground, and batch campaigns with cost estimated before dialling
  • Phone numbers: buy, or bring your own carrier (credentials encrypted and verified on connect); live transcripts and per-call cost
  • Team members can ring in and ask the assistant for practice figures — recognised by their mobile, refused politely if unknown

🏥 Practice management

  • Diary — day / 3-day / work-week / week views, drag to move, resize to extend, filters by practitioner and site, privacy mode with masked client names
  • Availability engine — rota, holidays, one-off changes, buffers, per-practitioner timezones, rooms: one source of truth the diary and the AI both use
  • Classes & group sessions — capacity, weekly runs, “places left” on the public page, a register with Arrived / Done / No-show per seat, and a wait-list that texts the front of the line a one-tap claim link when a place frees
  • Repeat series, appointment statuses, wait-list for private appointments, freed slots offered by text/email with single-use links
  • Clients — timeline, alerts, consents, a per-record access log (who opened whose record), CSV import (dry-run first) and export; records are always read from the server, never cached in the browser
  • Notes — per-service templates, incomplete flags, attachments, finalise-then-amend (finalised notes cannot be silently edited); receptionists cannot open clinical notes

💬 Messaging, money & public booking

  • SMS + email templates and rules (reminders, follow-ups, no-show chasing) with a sending window — nothing goes out at 3am; replies act: “yes” confirms, “no” cancels, “Thursday?” files a change request for the desk
  • Class packs — places paid for up front (“10 classes for $200”): booking holds a place, attending spends it, a late cancel or no-show burns it, an early one gives it back; unspent places can be refunded, packs extended or transferred — and the money is tracked as a liability until each class happens
  • Invoices from visits, draft → issued → paid / part-paid / overdue / void; payments, part payments, refunds, prepayments, credits, statements, expenses, revenue by practitioner
  • Public pay links, a per-practice online booking page, and a client’s own link to view, confirm, reschedule, cancel, and self-check-in
  • Reports — revenue by practitioner and service, utilisation, no-show rate, recalls, booking sources, with CSV export; analytics with a real CSV download; a whole-workspace JSON export with secrets redacted

🔧 Accounts, team & sales

  • Team roles (owner · admin · developer · receptionist · practitioner · viewer) enforced server-side, last-owner protection, session revocation
  • Self-serve signup, password reset, magic-link sign-in, emailed 7-day revocable staff invitations, email verification that genuinely gates publishing, numbers, and API keys
  • API keys, signed and retried webhooks, multiple workspaces per login, observability, API logs, and a full audit trail
  • Website enquiries become tracked sales leads with an inbox and pipeline; an operator growth funnel (signup → first call → first booking → got paid); a 57-page marketing site with full documentation

❌ What it cannot do Deliberately not there — and what exists instead

Multi-server / large multi-tenant deploymentA single-server database today, with a documented Postgres migration path
Off-site backups & built-in HTTPSBackups land on the same disk unless pointed elsewhere; HTTPS is terminated in front of the app
Telehealth video, stock/inventory, insurance claims, HL7/FHIROut of scope by decision
Full-text search of notes; a note-template editorTemplates with finalise/amend, without the editor
One honest detail: the demonstration workspace runs a rules engine rather than a live AI model. With provider keys configured, the identical call loop runs against a real model — the tools it can use are the same either way. Current verdict from our production review: ready for a single-site pilot; not yet for multi-tenant clinical deployment.
